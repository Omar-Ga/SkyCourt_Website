Prompt for AI Coder
Objective: Fix a layout animation "jump" in a React component where a motion component is placed next to static text.
Context:
I am working with two components: StatsSection.tsx and RotatingText.tsx. The StatsSection component displays a sentence where a static phrase is immediately followed by the RotatingText component, which animates through a list of strings. The RotatingText component has a colored background and changes width as the text inside it changes.
The Problem:
When the text inside <RotatingText> changes, the entire line of text "jumps" or "snaps" to its new position instead of animating smoothly. The layout prop from Framer Motion, which should handle this, is not working correctly.
Root Cause Analysis:
The core issue is mixing a raw text node (e.g., "The hub for ") with a motion component (<RotatingText />) inside a parent that has a layout prop (e.g., <motion.p layout>). Framer Motion's layout animation can only track and smoothly animate its direct children that are also motion components. The raw text node is not a motion component, so the browser reflows it instantly, which breaks the layout animation for the entire block.
Your Task:
Modify the provided code to fix this animation issue by ensuring all moving elements are motion components.
Specific Implementation Steps:
Modify StatsSection.tsx:
Ensure the parent element containing both the static text and the RotatingText component is a motion component (e.g., motion.p) and has the layout prop.
This is the critical fix: Wrap the static text part (e.g., {t('join_thousands')}{" "}) inside its own <motion.span> component.
Add the layout prop to this new <motion.span> so that it participates in the parent's layout animation.
To ensure proper vertical alignment after wrapping the text in spans, you can add flex items-center justify-center to the parent motion.p's class list.
Modify RotatingText.tsx (Recommended Refinement):
In the RotatingText.tsx file, locate the top-level motion.span that wraps the entire component.
Remove the transition prop from this specific motion.span. The layout prop should remain.
Reasoning: This allows the parent component (motion.p in StatsSection) to have sole control over the layout animation's physics (the spring transition), creating a single, coordinated, and smoother animation for the entire line.
